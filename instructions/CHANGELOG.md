# Instruction System Changelog

## 1.2.0 — 2026-08-17

- Removed mandatory human approval from routine ProjectPipeline development actions, including evidence-backed Jira `Done`, eligible PR merge, release publication, and branch/worktree cleanup.
- Replaced the human-work terminal with typed `BLOCKED_EXTERNAL` preconditions, autonomous recheck, and continuation of unaffected lanes.
- Preserved risk-based independent verification through policy-qualified automated receipts while explicitly removing GitHub human-review requirements from the normal protection target.
- Renamed the Jira completion control from a human gate to deterministic completion-evidence reconciliation and added validator/test coverage against regression.

## 1.1.0 — 2026-08-16

- Made objective before/after progress delta a governed Assurance capability derived from the original knowledge pack rather than caller-reported activity.
- Prohibited single-item lifecycle-only pull requests, required evidence-backed batch reconciliation for already-implemented work, and made the cohesive vertical slice the expensive-gate boundary.
- Added fail-closed Control routing for already-implemented/evidenced candidates, a two-cycle progressless stop, and a ten-percent noncritical administration ceiling.
- Added exact-base/head CI enforcement and instruction-validator regression checks so these delivery controls cannot be silently weakened.

## 1.0.1 — 2026-08-16

- Bound Jira preferred statuses to the live PP project's three-state collaboration workflow while preserving rich local lifecycle authority. The then-current human gate for remote Done was superseded in 1.2.0 by evidence-backed autonomous reconciliation.

## 1.0.0 — 2026-08-16

- Adopted `ProjectPipeline`, `PROJECT-PIPELINE`, `KevinSGarrett/ProjectPipeline`, and `C:\Project_X` as canonical identity.
- Added the root `AGENTS.md` bootstrap entry point and routed instructions `00` through `20`.
- Added machine-readable authority, coverage, context, branch/PR, CI, mutation, escalation, machine, PPQS, and scenario policies.
- Added repository-local procedures for bootstrap, Jira work, GitHub workflow, PPQS execution, upstream qualification, recovery, release, and CPU-worker dispatch.
- Added instruction schemas, templates, cold-start tooling, scenario tests, and a focused validator.
- Defined the host-validation boundary that preserves intentional PPQS negative fixtures while retaining benchmark files in the repository manifest.
- Tightened GitHub workflow action pinning, instruction ownership, PR evidence structure, and security analysis.
- Added an explicit second-pass register for live GitHub, Jira, upstream-workspace, CPU-worker, Windows, and optional quality-tool verification.

Version changes are meaningful contract changes, not wording counters. See `20_INSTRUCTION_MAINTENANCE.md`.
