## Requirements

- `REQ-AGENT-0001` — Agents, models, providers, and tools shall be registered and routed by qualified capability.
- `REQ-AGENT-0002` — External providers shall be isolated behind stable adapters and fallback policy.
- `REQ-AGENT-0003` — Model and tool versions shall require representative qualification before production eligibility.
- `REQ-AGENT-0005` — Task routing shall select an eligible capability first and only then select among providers or workers that supply it.
- `REQ-AGENT-0008` — Each capability shall define an ordered, policy-controlled fallback chain that can substitute local, subscription, API, or cloud execution without changing project semantics.
- `REQ-AGENT-0009` — Providers shall expose explicit healthy, degraded, unavailable, quota-limited, disabled, and recovery states used by routing decisions.
- `REQ-AGENT-0010` — Repeated provider or tool failures shall open a bounded circuit breaker, suppress unsafe retries, and allow controlled probes for recovery.
- `REQ-AGENT-0015` — The platform shall record success, latency, cost, retries, rework, review findings, and verified outcome quality by worker, model, provider, and task class.
- `REQ-AGENT-0016` — New model, tool, and adapter versions shall remain ineligible for production control until representative qualification and rollback readiness are recorded.
